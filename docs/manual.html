Your thoughts, kept beautifully.

Daftar V2 is a private, self-contained notebook for English and Persian writing—built for quick capture, thoughtful organization, recoverable editing, and optional local AI through Ollama.

The idea

A serious notebook without the ceremony.

Open one file and begin writing. Daftar keeps the immediacy of a scratchpad, then adds the organization, safety, bilingual controls, and AI workflow expected from a mature notebook.

Aa

English & Persian

Change the interface language independently from each note’s left-to-right, right-to-left, or automatic writing direction.

⌁

Private by default

Ordinary notes live in your browser profile. The notebook has no account, analytics, advertisements, or required cloud service.

✦

Optional local AI

Connect to Ollama to summarize, organize, polish, translate, extract key points, or follow your own instruction.

↶

Recoverable work

Autosave, emergency-draft recovery, snapshots, archive, and a recoverable trash reduce the cost of a wrong click.

Useful structure

Titles, topics, tags, stars, pins, full-text search, filters, and sorting help a quick note remain findable later.

⇩

Portable data

Export a full JSON backup, all live notes as Markdown, or the current note as plain text—and restore when needed.

Nothing to install for normal note-taking.

Keep Daftar-Local-Notebook-v2.html somewhere stable and open it with Chrome, Edge, Brave, Vivaldi, or another Chromium-based browser. No web server is required. Ollama is only needed for the optional AI tools.

01 · Quick start

Your first note, safely stored.

These five steps are enough to begin. Daftar saves edits automatically; there is no ordinary Save button to remember.

Open the notebook file

Double-click Daftar-Local-Notebook-v2.html, or right-click it and choose a Chromium-based browser. It is designed to run directly as a file:// page; do not change Ollama’s standard port or start a web server for Daftar.

Write immediately

Use the large editor for the note. The title is optional: if you leave it blank, Daftar uses the first non-empty line as the note’s display name.

Choose the writing direction

Leave direction on Auto for most notes. Choose LTR for English or RTL for Persian when you want explicit control.

Add structure only when useful

Give the note a topic and a few tags, then star important items or pin notes that should remain above the rest of the current list.

Make your first backup

Open Settings → Backup & data → Full JSON backup. Keep that file somewhere separate from the notebook. Repeat this habit periodically.

Autosave and snapshots are different.

Autosave continuously updates the current note. A snapshot is a named point in its history that you can restore later. Ctrl / ⌘ + S creates a snapshot; it is not required for ordinary saving.

04 · Organize

Capture first. Find it later.

Daftar lets a note begin unstructured, then gain just enough identity to remain useful months later.

Titles, topics, and tags

Title

Optional. If blank, the first non-empty line becomes the display title; otherwise Daftar shows “Untitled note.”

Topic

One broad, reusable category such as Research, Journal, Work, Ideas, or مطالعات.

Tags

Several specific labels. Type a tag and press Enter or comma; click a tag’s remove control to delete it.

AI organization

Title & organize suggests a concise title, one topic, and three to six tags without rewriting the note. You review the suggestion before applying it unless automatic application is enabled.

Search, filters, and sorting

  • Search looks across titles, note content, topics, and tags.
  • All shows normal notes that are neither archived nor trashed.
  • Starred gathers important live notes in one view.
  • Topics appear as filters when at least one note uses them; collapse the Topics heading whenever the list grows long.
  • Archive removes finished notes from the active workspace without deleting them.
  • Trash keeps removed notes recoverable until you delete them permanently.

Sort notes by Recently updated, Recently created, or Title A–Z. Pinned notes stay above unpinned notes except in Trash.

Age groups and deliberate cleanup

The note list automatically forms only the age groups that currently contain notes: Today, the previous 7 days, 1–2 weeks, 2 weeks–1 month, 1–2, 2–3, 3–4, 4–6, 6–9, and 9–12 months, 1–2 years, and more than 2 years. Each group is collapsible.

↻

Based on last activity

Groups use the note’s last-edited date. Manually revisiting an old note makes it current again because that activity signals continuing relevance.

⌫

Group-and-older cleanup

In the normal All view, a group’s trash icon moves that group and every older group to Trash after confirmation. Nothing is permanently erased at this stage.

Inside Trash, Empty Trash permanently deletes every trashed note after a second, explicit confirmation. Export a JSON backup before a large cleanup.

One-button AI Organize

The list-wide organizer is intentionally conservative.

The AI Organize button above the note list remains disabled until Ollama is connected and a model is selected. Once active, it checks non-trashed notes one at a time—including archived notes—and only processes notes that contain text and have at least one unfinished organization field.

  • An empty title, Untitled note, or the legacy default New Text counts as an unfinished title.
  • An empty topic or an empty tag list also makes the note eligible, even when the other fields are already complete.
  • Existing manual titles, topics, and tags are preserved; only empty or recognized default fields are filled.
  • Batch organization preserves the note’s last-edited time, so old notes do not jump to the top or move into newer age groups.
  • The animated button shows progress. Click it while running to stop safely; start it again later to continue with the remaining eligible notes.

Sidebar conveniences

Hover over a note card for quick Copy and Move to Trash controls. Drag the thin horizontal divider between filters/topics and the note count to give either region more room; double-click it to restore the default. The Topics heading and every age group remember whether you left them open or collapsed.

A new blank note does not multiply itself.

If the current note is completely empty, choosing New note reuses it instead of producing a pile of blank notes.

05 · Local AI

Bring your Ollama models into the notebook.

Daftar talks directly to Ollama from your browser. Once connected, you can run a local model such as Gemma 4 without copying notes into a separate chat window.

Normal note-taking never requires Ollama.

The AI panel is optional. If you never connect it, every other part of Daftar still works normally.

Set up Ollama: the clear path

Daftar’s documented Ollama prerequisite: allow browser origins once.

Daftar opens directly as a file:// page. Before relying on AI, explicitly set OLLAMA_ORIGINS to *, then quit and restart Ollama completely. Some current Ollama releases already recognize local-file origins, but this explicit setting removes version and profile ambiguity and is the supported Daftar setup.

Install or update Ollama

Install a current Ollama release for your operating system. Daftar uses Ollama’s normal local API at http://127.0.0.1:11434; it does not replace Ollama, start it for you, or require a different port.

Allow browser origins

Windows, recommended visual method: press Win, search for Edit the system environment variables, choose Environment Variables…, then under User variables create a variable named OLLAMA_ORIGINS with the value *.

Windows command-line alternative: open Command Prompt—use Administrator mode if required by your Windows policy—and run:

setx OLLAMA_ORIGINS "*"

macOS:

launchctl setenv OLLAMA_ORIGINS "*"

Linux, when starting Ollama yourself:

OLLAMA_ORIGINS="*" ollama serve

Restart Ollama completely

Environment-variable changes only reach newly started processes. On Windows or macOS, quit Ollama from its tray/menu icon—not merely its window—check that no old Ollama server remains, then reopen it. If you launch Ollama manually, stop the old ollama serve process before starting the new one.

On Windows, confirm the value from a new Command Prompt:

echo %OLLAMA_ORIGINS%

Install at least one model and verify Ollama

Pull any compatible model you want, then make sure it appears in the terminal. The first command below is only an example; use the exact model name appropriate to your installation.

ollama pull gemma4
ollama list

Open Daftar’s AI panel

Double-click Daftar as usual, click AI in the top bar, and leave the endpoint at http://127.0.0.1:11434. Daftar automatically removes a trailing /api if one is entered.

Connect, choose a model, and test

Click Connect. Daftar reads /api/tags, fills the model selector, and enables AI Organize after a model is selected. Write two or three sentences, choose Summarize, and inspect the rendered preview before applying anything.

OLLAMA_ORIGINS=* changes browser permission, not Ollama’s network address.

The wildcard lets browser pages on this computer request Ollama while it is running. Keep Ollama bound to loopback at 127.0.0.1; do not set a public OLLAMA_HOST, expose port 11434 to the network, or change Daftar’s address merely to solve CORS.

Local models, cloud models, and privacy

Local loopback + local model

With the default 127.0.0.1 address and a genuinely local model, note text is sent to Ollama on your own computer.

Cloud or remote endpoint

A model marked :cloud, or an Ollama server on another computer, may send or process note text beyond this device. Treat it accordingly.

The model selector favors an installed Gemma 4 model when one is available; otherwise it uses the first suitable model. You can always change the selection.

Keep-alive controls

Settings can ask Ollama to keep the model loaded for 5, 15, or 30 minutes, unload after the request, or remain loaded until Ollama stops. Longer keep-alive makes repeated tasks faster but continues using memory.

Connection says “Failed to fetch” or the Console reports CORS
  1. Confirm that ollama list works. This proves the service is running, but it does not prove that the browser origin is allowed.
  2. Keep Daftar’s address at http://127.0.0.1:11434. Do not substitute Daftar’s file location, a temporary web-server port, or 8765.
  3. Set OLLAMA_ORIGINS=* using the prerequisite steps above.
  4. Quit every running Ollama process completely, reopen Ollama, then reload Daftar and press Connect again.
  5. Press F12 → Console and read the first red CORS line if the failure remains.

If the Console says the response allows only a different origin, the old Ollama process is still using an earlier environment. Restarting the browser alone is not enough; the Ollama server itself must be restarted.

Advanced CORS preflight test on Windows

A Daftar page opened from disk sends the browser origin null. This command tests the exact POST preflight from Command Prompt:

curl.exe -i -X OPTIONS -H "Origin: null" -H "Access-Control-Request-Method: POST" -H "Access-Control-Request-Headers: content-type" http://127.0.0.1:11434/api/chat

A healthy preflight returns 204 No Content, permits POST and OPTIONS, permits content-type, and returns an Access-Control-Allow-Origin value that accepts the request. A plain curl GET can prove Ollama is alive while still missing a browser-only CORS problem.

The Console says file URLs are unique origins

Chrome may print a warning such as file: URLs are treated as unique security origins. If Daftar connects, saves, reloads, and runs AI normally, that warning is informational and can be left alone. The actionable failure is a blocked request to /api/tags or /api/chat.

No notebook web server is required. If you experimented with python -m http.server, harmless favicon.ico or DevTools 404 messages do not affect Daftar; simply return to the normal double-clicked file.

Connected, but no models appear

Ollama is reachable but has no compatible installed model. Check the terminal with ollama list, pull a model, and reconnect. If the model exists under a different Ollama installation or user account, make sure Daftar is connecting to the server that owns it.

The first answer is slow

The model may need to load from disk into memory. Later requests are usually faster while it remains loaded. Choose a longer keep-alive value for repeated work, or a smaller model when memory is limited.

How “Use selected text” works

Highlight part of the editor, then enable Use selected text. The AI receives that selection instead of the full note. If no valid selection exists, Daftar tells you rather than silently using the whole note.

How to stop a generation

Choose Stop in the AI output area. The partial preview remains visible, but Daftar will not modify your note until you explicitly choose an output action.

Keep Ollama on loopback unless you intentionally need network access.

The default 127.0.0.1 address limits the service to your own machine. Do not expose Ollama to a local network or the internet merely to make this notebook connect.

In Settings, choose Import / restore, then select a supported file. Daftar can understand:

  • JSON arrays or objects containing notes or history.

Before upgrading or moving Daftar, export JSON first.

10 · Privacy

Understand exactly where your words go.

Daftar is local-first, but “local” has precise boundaries. This section makes those boundaries plain.

⌂

Notebook data

Notes and settings are stored in the current browser profile, primarily through IndexedDB with a localStorage fallback. Clearing site data can erase them.

AI

AI requests

Only text you deliberately submit through an AI action or the list-wide AI Organize process is sent to the configured Ollama endpoint. The destination depends on that address and the selected model.

  • No Daftar account or sign-in is required.
  • No analytics, ads, or third-party scripts are included.
  • Normal writing does not contact Ollama.
  • Daftar stores no online-AI API key because this version intentionally includes no direct cloud-API provider.
  • The manual and notebook can open without internet access.
  • A loopback Ollama server stays on this computer.
  • A remote or cloud model deserves normal cloud-data caution.
The origin wildcard is permission, not isolation.

OLLAMA_ORIGINS=* permits browser origins to call the API. The protection that keeps Ollama on this computer is its loopback binding and your firewall. Keep the endpoint at 127.0.0.1:11434, close Ollama when you are not using it, and do not open untrusted browser pages while a broadly permitted local service is running.

Local storage is not the same as a backup.

Your browser profile is a working location, not an archival guarantee. Clearing browser data, using a cleanup utility, losing the device, or switching profiles can remove access. Export JSON regularly.

Legacy notebook import

When Daftar first opens in the same browser profile as the earlier Local Notebook, it looks once for that notebook’s textEditorHistory data and imports it automatically when available. If the old data lives in another browser profile or storage origin, use an export/import route instead.

11 · Help

When something feels wrong.

Start with the symptom. Most issues come from browser storage boundaries, an Ollama service that is not running, or a file opened in a different browser profile.

My notes seem to be missing
  1. Confirm that you opened the same Daftar HTML file, in the same browser and browser profile.
  2. Check All, Archive, Trash, Starred, and topic filters; clear the search field.
  3. If you recently moved or renamed the file, reopen the original location.
  4. If you have a JSON backup, use Settings → Import / restore.

Do not clear browser data while investigating.

The save status shows an error

First copy the current note text somewhere safe. Then export a JSON backup if the command still works. Browser storage may be unavailable, full, blocked by private browsing policy, or damaged. Try the canonical notebook file in a normal browser window and avoid aggressive storage-cleanup extensions.

Persian text direction looks wrong

Set that note to RTL instead of Auto. For English-heavy notes choose LTR. Interface language is separate, so changing English/فارسی in Settings will not repair an individual note’s direction.

A chosen font does not look different

The Daftar font is embedded, but several other choices depend on fonts installed on your computer. If a chosen font is missing, the browser uses a fallback. Install that font locally or return to Daftar, Tahoma, Segoe UI, Georgia, Times New Roman, or Monospace.

Search does not find a note

Search examines title, content, topic, and tags, but the current view still matters. Clear the search, switch to All, Archive, or Trash as appropriate, and try a shorter distinctive phrase.

I accidentally replaced text with AI

Open the note’s More menu, choose Version history, and restore the safety snapshot created before the AI change. Daftar preserves the pre-change state precisely for this situation.

I accidentally deleted a note

Open Trash, select the note, open More, and choose Restore. If you already chose Delete permanently and confirmed it, restore from a JSON backup; permanent deletion is not reversible inside the live notebook.

The AI answer is weak or in the wrong style

Try a more capable model, improve the action’s editable prompt, add a precise system-prompt preference, or use Use selected text to reduce irrelevant context. For example: “Rewrite only for clarity; keep my voice, paragraph order, facts, and Persian terminology.” Always review model output before applying it.

The AI cannot replace the note because it changed

This is intentional protection. You edited the source while the model was generating, so the old result may no longer match. Copy the preview if useful, then run the action again against the current text.

AI Organize skipped a note

The note must contain text, must not be in Trash, and must have an empty/default title, empty topic, or empty tag list. Recognized default titles include Untitled note and the legacy New Text. A fully organized note is intentionally skipped. If the model returned incomplete metadata or the note changed during the request, run the organizer again.

Markdown marks are visible in the editor

This is the intended source view, not a formatting failure. Choose Preview to render **bold**, headings, lists, and quotes visually. Use Copy for readable text or More → Copy as Markdown to preserve the marks.

The notebook sidebar appears closed

Use the permanent hamburger button at the notebook edge. On mobile it opens the sidebar as an overlay; on desktop it restores the saved width. If an older Daftar build lost the reopen control after a language change, open the current V2 file—do not delete browser storage or your notes.

A keyboard shortcut does not work

Open Settings → Help → Keyboard shortcuts and confirm the current assignment. Formatting shortcuts only run while the note editor is active. Browser extensions and operating-system utilities can reserve combinations; record another one if necessary. Choose Reset shortcuts to restore the documented defaults.

The interface feels crowded on a small screen

Collapse Topics and old age groups, drag the sidebar’s horizontal divider, use the sidebar toggle, Focus mode, or Preview. Daftar adapts to narrow screens, but long writing sessions are naturally more comfortable in Focus mode.

A five-minute health check

  • Create a short test note and verify the status becomes Saved.
  • Refresh the page and confirm the test note remains.
  • Create and restore one snapshot.
  • Export a JSON backup and confirm it downloads.
  • If using AI, connect and summarize the test note.
  • Keep the successful notebook file in one stable location.

Keep writing. Daftar will keep the room ready.
